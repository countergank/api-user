# Use canonical commit types with SemVer impact mapping

**Do**: Use exactly one of the 11 canonical types below as the commit header prefix. Match the type to the actual change being made, not to the perceived importance.
**Avoid**: Inventing custom types (e.g., `update`, `change`, `wip`, `temp`, `patch`), mixing multiple types in a single commit, or using types as emotional emphasis (e.g., `feat` for a trivial change).
**Reference**: [Conventional Commits 1.0.0](https://www.conventionalcommits.org/en/v1.0.0/)

## Canonical Types

| Type | Description | SemVer Impact |
|------|-------------|---------------|
| `feat` | A new feature or user-visible capability | `MINOR` |
| `fix` | A bug fix that corrects broken behavior | `PATCH` |
| `docs` | Documentation-only changes (README, guides, comments) | None |
| `style` | Code style changes (formatting, whitespace, semicolons) — no logic change | None |
| `refactor` | Code restructuring that neither fixes a bug nor adds a feature | None |
| `perf` | A change that improves runtime or memory performance | `PATCH` |
| `test` | Adding or correcting tests — no production code change | None |
| `build` | Build system or external dependency changes (webpack, npm, pip) | None |
| `ci` | CI/CD configuration changes (GitHub Actions, Jenkins, Travis) | None |
| `chore` | Maintenance tasks, tooling, config — no user-facing change | None |
| `revert` | Reverting a previous commit (auto-generated by `git revert`) | Inverse of original |

## SemVer Mapping Rules

- `feat` → bump **MINOR** version (`1.2.0` → `1.3.0`)
- `fix`, `perf` → bump **PATCH** version (`1.2.0` → `1.2.1`)
- `feat` + `BREAKING CHANGE` → bump **MAJOR** version (`1.2.0` → `2.0.0`)
- All other types → no version bump by default (internal only)

## Alias Handling

Some teams use aliases. Map them to the canonical type before committing:

| Alias | Maps To |
|-------|---------|
| `bug`, `bugfix`, `hotfix` | `fix` |
| `feature` | `feat` |
| `doc`, `documentation` | `docs` |
| `formatting`, `lint` | `style` |
| `cleanup`, `restructure` | `refactor` |
| `deps`, `dependency` | `build` |
| `maintenance`, `task` | `chore` |

**Example** — correct type selection:
```
feat(auth): add OAuth2 login with Google provider
fix(api): handle null user preferences without 500 error
docs(readme): add quickstart section for local development
chore(deps): update eslint to v9.0.0
```

**Example** — invalid type (reject):
```
update(auth): change login flow          ← use feat or refactor
wip: working on user profile             ← never commit WIP
patch(api): fix typo in error message    ← use fix or docs
```
